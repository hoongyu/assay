# 本批小结：Nemotron 写文字，数字由拣金填（设计）

2026-10-05。用户 2026-10-05 定：Nebius 赛道不租 GPU，只用比赛送的 Token Factory 额度调 Nemotron；用途是「每批小结和采集员反馈」，中文、英文各一份。用户批了这份设计，写完直接做。

## 1. 为什么

- Nebius 赛道要求运行时调用 Token Factory 的推理接口（或者用 AI Cloud 的 Serverless），并且用至少一个 NVIDIA 开源模型（设计文档第 7 节，2026-10-05 核）。Token Factory 上能看视频的 NVIDIA 模型 2026-08-31 都下线了，剩下的是文字模型。
- README 里「说清原因，可以按采集员汇总，每班反馈」现在只有一张统计表。质检组长要的是一段能直接转给采集员的话：这一批主要出了什么问题、先看哪几条、下一班注意什么。

## 2. 先搜过的

本地语料库没有对得上的。GitHub 上的 RefChecker、SelfCheckGPT 是用另一个模型去抽取说法、逐条核查，对这里太重：这里的事实都是拣金自己算出来的数。所以从构造上堵住编数：模型只写文字，数字由代码填。

## 3. 怎么做

- 事实：从判定结果算，包括总条数、合格、存疑、作废的条数；报出的原因按示范计、取最多的五类，每类的条数、占比和最多三条示范编号；没查的项目和条数；有采集员编号时，每人的条数、存疑加作废的条数、最多的原因。每个事实有一个占位符名（英文字母和下划线），中文、英文各有一套取值（原因名有英文对照）。
- 模型：Token Factory 的 OpenAI 兼容接口 `https://api.tokenfactory.nebius.com/v1/`，默认 `nvidia/Nemotron-3_5-Lightning`（30B，每次激活 3B，OpenMDW-1.1，权重公开、不用申请）。密钥从环境变量 `NEBIUS_API_KEY` 读，只在用户自己的终端里设，不进仓库。用标准库发请求，不加依赖。回答里带 `<think>` 的推理段先去掉。
- 写法：给模型事实（带占位符名）和要求：写给质检组长和采集员的一段话，中文不超过 200 字、英文不超过 120 词；所有数量、示范编号、原因名都写成 `{占位符}`，自己不写数字；建议只能根据给出的原因写。
- 核对：输出里不许有阿拉伯数字，不许有「二」到「万」这类汉字数字接量词（「一」太常见，放过），英文不许有 two 到 twenty、hundred、thousand、dozen；占位符必须是给过的。不合格就把问题列给模型重试一次，还不行就退回模板文字。
- 模板：同样的事实按固定句式写，中文、英文各一份。没设密钥时也用模板。
- 缓存：按「模型、提示版本、语言、事实」的哈希存回答（`cache/summary/`），重出报告不用再调，也不再花额度。
- 报告：`jianjin check --summary` 时，报告顶部多一节「本批小结」，中英两段，注明是 Nemotron 写的还是模板，以及「数字由拣金填」。不加 `--summary` 时报告和现在一样，断网能开。

## 4. 不做的

- 不让模型看示范数据本身（关节、视频），只看拣金算出的统计；出场的只有统计数字和示范编号，没有原始数据。
- 不做逐条示范的解释：体检单上的证据已经是人话。
- 不让模型判定任何东西，判定仍然只来自规则。

## 5. 风险

- 模型可能把占位符放错地方（比如把存疑条数说成作废条数）。数字对，意思错。缓解：占位符名起得直白；报告里写明是模型写的，按统计表为准。
- 公开数据没有采集员编号，演示时只看得到「本批小结」，按人的那部分只在测试里。
- Token Factory 的模型会下线（8 月那轮下了 10 个）；模型名做成参数。
