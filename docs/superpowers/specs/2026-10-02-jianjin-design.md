## 1. 问题

具身智能的训练数据主要靠遥操作采集：采集员操纵主臂，机器人跟着做，录下视频和关节数据。国内为此建了一批数采场。

| 事实 | 来源 |
|---|---|
| 全国至少 15 座规模较大的数采场，占地多在 3,000 到 5,000 平米 | 《中国经营报》统计，甲子光年 2026-06-26 引用 |
| 大型数采场投入大多在一亿元以上，基本没有盈利 | 甲子光年，一位大型数采场负责人匿名说的 |
| 北京人形机器人创新中心的基地有 120 多台机器人，数据卖 500 到 1,000 元一小时 | 甲子光年 |
| 同一个动作要重复 700 多遍（遥操作）；过快或多余的动作会让数据作废（穿戴设备采集的试岗培训） | 甲子光年 |
| 质检和标注大量靠人工；「可能你采了 100 个小时，漏斗筛选下来只有 50 个小时有效」 | 甲子光年，同一位负责人的估计，不是行业统计 |

2026-10-04 回原文核过，逐条记录在背景资料。原来还有一条「一班约 8 小时，实采 6 小时，过三道质检后剩 3 到 4 小时有效」，列的出处里都找不到，删了，路演不用。

痛点归结为两条：

1. 坏示范靠人一条条看，慢，而且贵。
2. 作废的原因没有回流给采集员，同样的错下一班还会再犯。

## 2. 用户和卖点

- 买单方：具身智能数采场，以及自建遥操作团队的机器人公司。
- 使用者：质检员和数采场主管；采集员每班收到反馈。
- 一句话：录完的每条示范，拣金自动判成「合格」「存疑」「作废」，作废的写清原因和出问题的时间点。质检员只看存疑的，采集员每班拿到自己的问题清单。

卖点三条：

1. 说得清原因：不只给分数，还指出第几秒出了什么事、属于哪一类失败。
2. 人只看存疑的：人工质检从「每条都看」变成「只看机器拿不准的」。
3. 数据不出场：数采场的数据就是它卖的货。拣金在本地跑，关节体检用笔记本，视频评判用场内显卡，报告是离线的单个网页文件。

## 3. 范围

必做：

1. 读入 LeRobot（v3）和 RoboMIND（HDF5）两种格式，统一成一种示范结构。
2. 关节体检，只用 CPU。
3. 视频评判：Robometer-4B 和 TOPReward 两个适配器。
4. 诊断：合并信号，出判定、原因和时间点。
5. 离线单文件网页报告：每条示范一张体检单，加整批数据的作废漏斗；数据里有采集员编号时，再按人统计问题分布。公开数据没有采集员编号，演示里这一栏会是空的，等试点数据。
6. 评测脚本：三张考卷，见第 6 节。
7. 第 4 周加 Cosmos 3 适配器，给 Nebius 赛道用，见第 7 节。

可做：

- 进度曲线的交互查看。
- 同一任务里不同采集员的对比视图。

不做：

- 实时接入数采场的采集流水线。
- 训练策略来证明筛选有效。
- 任何硬件。
- 云服务（和「数据不出场」冲突）。

## 4. 架构

Python 3.12，uv 管依赖，pytest 测试，和烽燧、虎符一样。

核心只依赖 numpy、h5py、pyarrow 和一个视频解码库，直接读文件格式，不 import LeRobot。视频评判的模型依赖（torch、transformers 等）放进可选的 `judges` 依赖组，没装也能跑关节体检。

### 4.1 模块

| 模块 | 干什么 | 输入 | 输出 |
|---|---|---|---|
| `ingest` | 读 LeRobot v3 和 RoboMIND HDF5 | 数据集路径 | `Episode` 序列 |
| `checks` | 关节体检，每条规则一个纯函数 | `Episode` | `Finding` 列表 |
| `judges` | 视频评判适配器：Robometer、TOPReward、Cosmos 3 | 视频和任务描述 | 每帧进度和成功概率，或文字解释 |
| `diagnose` | 合并信号，出判定 | `Finding` 列表和评判结果 | `Verdict` |
| `report` | 生成离线单文件网页 | `Verdict` 序列 | 一个 HTML 文件 |
| `eval` | 跑三张考卷 | 考卷数据和标签 | 指标表，带分母 |

### 4.2 数据结构

- `Episode`：`id`、`source`、`task`（任务描述）、`fps`、`cameras`（各路视频的读取器）、`state`（关节状态，T×D）、`action`（动作，T×D）、`gripper`（夹爪开合，能识别时才有）、`operator_id`（有才填）、`meta`。
- `Finding`：`check`（哪条规则或哪个模型）、`cause`（失败原因类别，见第 5 节）、`t0` 和 `t1`（秒）、`score`、`evidence`（一句人话）。
- `Verdict`：`label`（合格、存疑、作废）、`causes`（`Finding` 列表）、`not_checked`（没查的项目和原因）、`progress`（进度曲线，跑了视频评判才有）。

实现时的出入（2026-10-02，第一周计划）：`Episode` 加了 `timestamps`、`state_names`、`gripper_index`，`gripper` 改成按 `gripper_index` 从 `state` 取的属性，注入缺陷时夹爪不会和关节错位；`Finding` 加了 `hard`，标记客观硬规则。

### 4.3 判定规则

错杀比漏判贵：一小时数据卖 500 到 1,000 元，误判作废一条就是白扔钱。所以判定偏保守：

- 作废：至少两个彼此独立的信号指向同一处问题，或者一条客观硬规则触发（比如数据截断、关节读数缺失）。「独立」指来源不同：关节规则算一个来源，每个视频模型各算一个来源；「同一处」指两个信号报出的时间区间有重叠。
- 存疑：只有一个信号触发，或者两个视频模型的结论相反。
- 合格：其余情况。
- 缺了某种数据（比如没有夹爪通道），对应的规则记进 `not_checked`，不当成通过。

阈值在考卷 A 的开发集上定，测试集只用来报成绩。

实现时的出入（2026-10-03，第三周计划）：

- 「同一处」改成：时间区间重叠，而且原因相同，或者两条都只占示范的一段。只看重叠不够，「指令不符」「多余动作」这类发现覆盖整条示范，和什么都重叠。
- 视频规则两条，阈值出处：
  - 「指令不符」：Robometer 的全程最高进度和同一任务描述下那批示范比，低出 1.548 个四分位距以上就报。阈值在考卷 A 换描述的 dev 上定，原样报出不超过 5%。
  - 「物体掉落」：Robometer 的进度从此前最高点往下掉超过 0.239 就报，只看关节数据有的时间里、手臂开始回原位以前。阈值是 RoboVAD train 正常示范的 95 分位。（第四周 a 改，原来看整条、阈值 0.345，见考卷 B 第五批。）
  - TOPReward（2026-10-04 起）只用「指令不符」：结尾「True」的概率和同一任务描述下那批比，低出 3.321 个四分位距以上就报，阈值同样在考卷 A 换描述的 dev 上定（考卷 A 第四批）。它的「物体掉落」在 train 上定过阈值，但开发数据集的成功示范上误报太多，没启用，报告里记进没查（考卷 B 第六批）。
  - 两条视频规则都只看关节数据有的时间里的曲线：视频比关节长时，多出来那段不算这条示范的。
- 第四周 a（2026-10-03）加了「视频和关节数据时长对不上」，只读元数据、不解码视频：视频比关节短是硬规则（最后一段关节数据没有画面，训练时取不到帧）；视频比关节长记存疑，来源算「元数据」。差一帧半以内不算。
- 第四周 b（2026-10-03）加了关节规则「空录」（手臂整条几乎没动），和一组「原因不同、说的是同一件事」：两个来源各报一条整条的发现，一条是「空录」、一条是「指令不符」，都是说这条没做指令里的任务，算指向同一处问题，判作废。
- 第四周 d（2026-10-04）加了关节规则「二次抓取」：夹爪开合次数（中间那种在一档里待不够 0.2 秒、又回去的不算）超过同任务那批的 75 分位加 1 次就报，读从臂；读哪一路、余量在 RoboVAD train 上选（考卷 B 第七批）。时间段写整条示范，所以只有它一条时判存疑，不会和别的来源报的不同原因凑成作废。
- 第四周 e（2026-10-05）加了关节规则「动作不流畅」：示范用时超过同任务中位数的 1.7 倍就报。原想数中途停顿、动作段数、jerk，在 RoboMIND 的失败示范上这几个都反着报（考卷 C），按事先定的规矩只留时长；时间段写整条示范，只有它一条时判存疑。「速度过快」试了最快速度、平均速度，开发集上一条没检出，没加。
- 现状（2026-10-04）：视频来源有 Robometer 和 TOPReward 两个。作废来自硬规则、两条都局部且时间重叠的发现、「空录」加「指令不符」这一对，以及两个视频模型都报同一条「指令不符」。考卷 A 换描述 test 上，换了描述的 115/201 两个模型都报，原样示范 0/201；RoboVAD 上这样判作废的 18 条里 10 条有异常标注（见「整条判定」一节）。

### 4.4 降级和出错

- 没有 GPU，或者没装 `judges` 依赖：只跑关节体检，报告顶部写「没跑视频评判」。
- 某条示范读不了：记进报告的「读取失败」一栏，不中断整批。
- 模型输出按「示范内容哈希加模型版本」缓存成旁路文件，不改原数据；换了模型不会读到旧结果。

### 4.5 命令行

```
jianjin check <数据集路径> [--out 报告.html] [--json 明细.json] [--judges robometer,topreward] [--cache cache] [--camera 相机] [--no-frames]
jianjin eval a|a-swap|b|b-episode [--split dev|test|train|validation] [--dev-result 结果.json] [--judge robometer]
jianjin judge <robovad|exam_a|数据集路径> [--judge robometer|topreward]   # 在有 GPU 的机器上跑，结果写进缓存
jianjin fetch [exam_a|robovad] [--videos]
```

`check` 认得 LeRobot v3、RoboMIND HDF5 和 RoboVAD 目录。视频评判只读缓存，本机不需要 GPU；缓存在 Colab 上用 `notebooks/` 里的笔记本跑。（2026-10-03 按实现改写）

本机有视频时，报告给存疑、作废的体检单配几张关键帧（每条发现的起止时刻；整条的发现取开头、中间、结尾；视频比关节长的再取一张多出来那段的），JPEG 嵌在 HTML 里，报告还是一个文件。`--no-frames` 关掉。（2026-10-03 第四周 a）

## 5. 失败原因分类

先用下面七类。拿到 RoboMIND 的失败标签后，按它的分类对齐。

2026-10-02 核：RoboMIND 公开的失败示范把原因写成中文目录名，共 11 类（括号里是条数）：动作不流畅（557）、二次抓取（284）、触碰多余（232）、夹取前碰撞（217）、目标移位（118）、失败放置（113）、轨迹异常（39）、动作不规范（38）、速度过快（36）、机械臂异常（17）、夹爪出境（15），另有 12 条没有原因目录。论文里是另一套 9 类，两套对不上，以公开数据的 11 类为准。原来写的「定位不准占 48%」是论文里 ACT 策略在人形机器人任务上测试时的失败统计，不是遥操作示范的失败，不能这么引。和拣金规则的对应见本节末尾（2026-10-04）。

| 类别 | 主要靠什么发现 |
|---|---|
| 没做完 | 视频进度曲线没到头，示范在任务完成前结束 |
| 空录 | 手臂整条几乎没动（离开头姿态最远不到同任务中位数的 0.2），录下的不是示范；2026-10-03 因叠方块 ep 39、55 加 |
| 定位不准 | 接近目标时反复来回修正，视频进度停滞（还没有规则） |
| 夹爪没合上（抓空） | 夹爪闭合后进度不涨，闭合幅度异常（还没有规则） |
| 二次抓取 | 夹爪开合次数比同任务那批常见的多（关节数据）；2026-10-04 加，见考卷 B 第七批 |
| 动作不流畅 | 用时比同任务中位数长 1.7 倍以上（关节数据）；2026-10-05 加。停顿次数、jerk 这类平顺度指标在 RoboMIND 上反着报，没用上，见考卷 C |
| 物体掉落 | 夹爪中途意外张开，或者进度曲线突然回落 |
| 多余动作 | 路径长度远超必要，动作和任务无关 |
| 停顿过长 | 关节速度长时间接近零 |
| 指令不符 | 视频评判认为做的不是任务描述里的事 |
| 数据异常 | 读数缺失、丢帧、示范过短；客观硬规则，一条就能判作废 |

### 和 RoboMIND 11 类的对应（2026-10-04）

RoboMIND 没给这 11 类下定义：数据卡、`static/` 下的说明、ModelScope 上 V2.0 的说明里都没有。下面按类别名的字面意思，对拣金已经实现的规则。「对得上」只说有一条规则是冲着这类问题去的，不说能抓到多少；2026-10-05 起考卷 C 在 RoboMIND 上量了其中两类，数写在说明里。分母是公开的 1,678 条失败示范。

| RoboMIND 的原因 | 条数 | 拣金现在 | 说明 |
|---|---|---|---|
| 动作不流畅 | 557 | 对得上 | 2026-10-05 加了「动作不流畅」，看的是用时（超过同任务中位数 1.7 倍）；考卷 C 测试集检出 26/187 = 14%，同任务其他原因报出 4%。数停顿、jerk 在 RoboMIND 上反着报，没用上 |
| 二次抓取 | 284 | 对得上 | 2026-10-04 加了「二次抓取」规则（考卷 B 第七批）；考卷 C 在 RoboMIND 上检出 99/162 = 61%，同任务其他原因报出 7%，参数没在 RoboMIND 上调 |
| 触碰多余 | 232 | 查不了 | 碰了不该碰的东西，要看画面 |
| 夹取前碰撞 | 217 | 查不了 | 要看画面 |
| 目标移位 | 118 | 查不了 | 物体被碰走，要看画面；因此没做完的，会落到「没做完」「指令不符」 |
| 失败放置 | 113 | 对得上 | 没放好就是没做完：关节的「没做完」看收尾姿态，视频的「指令不符」看进度或完成概率比同批低；报出的原因名不叫「失败放置」 |
| 轨迹异常 | 39 | 部分 | 路程远超常态的，「多余动作」抓得到 |
| 动作不规范 | 38 | 查不了 | 违反采集规范，要看画面，还得知道规范是什么 |
| 速度过快 | 36 | 查不了 | 2026-10-05 试了和同任务那批比最快速度、平均速度，考卷 C 开发集 17 条一条没检出，没加规则 |
| 机械臂异常 | 17 | 部分 | 读数断了、时间戳乱了的，「数据异常」抓得到；停住不动的，「停顿过长」抓得到 |
| 夹爪出境 | 15 | 查不了 | 夹爪跑出画面，要看画面 |
| 没有原因目录 | 12 | | |

合计：对得上 954 条（56.9%），部分 56 条（3.3%），查不了 656 条（39.1%），没有原因 12 条。量过的两类，检出差得远：二次抓取 61%，动作不流畅 14%。加「动作不流畅」以前是对得上 397 条（23.7%）、部分 613 条（36.5%）；加「二次抓取」以前是对得上 113 条（6.7%）、查不了 940 条（56.0%）。

- 北京人形判不合格的，大头是动作质量：不流畅、二次抓取、多余触碰、夹取前碰撞，任务本身多半做完了。拣金现在查的是数据坏没坏、任务做没做完、做的是不是这个任务，正好是另一头。视频模型问的是「完成了吗」，这类示范多半会被判完成。
- 补规则按条数和难易排：二次抓取（284 条）2026-10-04 加了；动作不流畅（557 条）、速度过快（36 条）2026-10-05 做了，只加了一条看用时的「动作不流畅」（考卷 C）；要看画面的五类（触碰多余、夹取前碰撞、目标移位、动作不规范、夹爪出境，共 620 条）留给视频模型，可以试 Cosmos 3 这类能回答具体问题的模型。
- 加规则时，阈值仍在成功示范上定（考卷 A 的 SO-10x 数据集、RoboVAD 的正常示范）；RoboMIND 的失败示范只拿来量检出。没有同批的成功示范，误报在它上面量不了；考卷 C 拿同任务其他原因的失败示范当参照，报它们被报出的比例，代替误报。

## 6. 验证：三张考卷，都不用机器人

### 考卷 A：注入缺陷（主开发集）

在真机录的成功示范上动手脚，每条的答案已知：

- 截掉结尾，对应「没做完」。
- 插入静止帧，对应「停顿过长」。
- 换掉任务描述，对应「指令不符」。

数据用 LeRobot Hub 上公开的 SO-101 示范（只选授权写明的），拿得到 RoboMIND 就加上它的成功示范。

指标：每类缺陷的检出率和误报率（按示范计）；报出的时间点是否落在注入的区间里。按任务切开发集和测试集，不按示范随机切。

报告里写明：这是在真数据上造出来的假失败。

#### 第一批结果（2026-10-02，只用关节数据，没跑视频评判）

#### 第二批结果：换掉任务描述（2026-10-03，视频评判 Robometer-4B）

2. RoboMIND：失败示范有没有公开、在哪里、原因怎么标。
3. RoboVAD：数据量、格式、有没有关节数据、评测协议。
4. Robometer-4B 用 BF16 要多少显存；社区 4 位量化版的授权和精度损失。
5. TOPReward 包的是哪个尺寸的 Qwen3-VL，要多少显存。
6. Cosmos 3 的授权，以及在 Nebius 上能不能直接调用；不能就在 Nebius AI Cloud 的 GPU 机器上自己跑。
7. 租 GPU 的价格。

每一条核完，结论写进本文对应的小节。

2026-10-02 核了第 2 到第 7 条（一个调研 agent，45 次工具调用，约 12.4 万 token）：

| 条目 | 结论 | 写在哪 |
|---|---|---|
| 1 参赛指南 | 没核，要加微信领 | 用户 |
| 2 RoboMIND | 失败示范公开了 1,678 条，原因 11 类 | 第 5 节、考卷 C |
| 3 RoboVAD | 6.86 GB，有关节数据；授权按 CC BY-NC-ND 处理 | 考卷 B |
| 4 Robometer-4B | BF16 权重 8.90 GB，社区 NF4 版卡上写最低 3.6 GB 显存；官方没写显存，NF4 的精度损失没人报告过（Apache-2.0） | 这里 |
| 5 TOPReward | 默认包 Qwen3-VL-8B-Instruct，权重约 16 GB；显存要求文档没写，按 BF16 估至少 24 GB 档（推测）。2026-10-04 实测：改用 4B，半精度直接加载到 Colab T4，显存 8.9 GB，每条约 0.5 秒（8B 在 10-02 摸底时撑爆了内存） | 这里 |
| 6 Cosmos 3 | OpenMDW-1.1 可商用；Token Factory serverless 已下线 | 第 7 节 |
| 7 GPU 价格 | Nebius 按需（美元/卡·小时）：L40S 48 GB 起 1.55，H100 80 GB 3.85，H200 4.50，没有 24 GB 档。AutoDL 官网要登录，只拿到第三方 2026-07 的报价：4090 24 GB 约 2.19 元/时、A800 80 GB 约 6.29 元/时，未核一手 | 这里 |

考卷 A 用的五个数据集（核过 `meta/info.json`，都是 v3.0、30 fps、有夹爪通道）：`lerobot/svla_so100_pickplace`、`lerobot/svla_so100_stacking`、`lerobot/svla_so100_sorting`、`lerobot/svla_so101_pickplace`、`CoRL2026-CSI/SO101-DualArm-teleop_fold_towel_100epi`，数据卡 YAML 都写 Apache-2.0，正文还没逐个看。

## 11. 只能用户来做的事

海创π 报名、Nebius 提交、RoboMIND 下载时同意共享联系方式、租 GPU 付款、联系数采场试点。项目窗口只把材料准备好。

## 12. 求职叙事

- 具身智能的数据工程：从数据格式、质检规则到评测基准，一条链做通。
- 人在回路的流程设计：质检员只看存疑、采集员每班收反馈，对上「人因方向 UX 研究」和「技术产品」两类目标岗位。
- 诚实的评测：每个数字带分母，分清真实失败和注入的缺陷。
