# 拣金 jianjin

数采场示范数据的自动质检。录完的每条遥操作示范，拣金自动判成「合格」「存疑」「作废」，写清原因和出问题的时间点：质检员只看存疑的，作废的每条都有依据。全部在本地跑，报告是一个断网也能打开的网页文件，数据不出场。

参赛：首届「海创π」未来产业创新创业大赛·具身智能专项赛；Nebius × NVIDIA Global AI Hackathon 的 Physical AI 赛道。

## 为什么做

具身智能的训练数据主要靠遥操作采集：采集员操纵主臂，机器人跟着做，录下视频和关节数据，国内为此建了一批数采场。据行业报道，采到的示范要过几道人工质检，相当一部分会作废；作废的原因也很少回流给采集员，同样的错下一班还会再犯。报道出处见[背景资料](docs/research/2026-10-02-background.md)；具体数字写进路演材料以前，会回原文再核一遍。

拣金做两件事：

1. 机器先筛一遍，人只看机器拿不准的。
2. 说清原因：哪一秒、哪一类问题，可以按采集员汇总，每班反馈。

## 怎么判

| 看什么 | 查什么 | 报出的原因 | 要什么 |
|---|---|---|---|
| 元数据和关节读数 | 读数缺失；时间戳丢帧或倒退；示范过短；视频比关节数据短 | 数据异常（客观硬规则，一条就作废） | CPU |
| 元数据 | 视频比关节数据长，两路没对齐 | 数据异常（存疑） | CPU |
| 关节 | 中途停住太久 | 停顿过长 | CPU |
| 关节，和同任务那批示范比 | 路程远超常态；收尾姿态不像做完了；整条几乎没动 | 多余动作、没做完、空录 | CPU |
| 视频评判（Robometer-4B，零样本） | 全程进度比同任务那批低得多；进度突然往回掉 | 指令不符、物体掉落 | GPU，结果缓存 |

判定偏保守，错杀一条好数据比漏掉一条坏数据贵：

- **作废**：客观硬规则触发；或者两个独立来源（关节规则算一个，每个视频模型各算一个）指向同一处问题。
- **存疑**：有发现，但够不上作废，要人看。
- **合格**：什么都没报。没查的项目（比如没有视频、同任务示范太少、这批示范收尾姿态本来就不固定）单独列出，不当成通过。

报告里有整批的判定漏斗、问题分布、按采集员的统计（数据里有采集员编号时），以及每条示范一张体检单：判定理由、进度曲线、出问题的时间段、关键帧缩略图。

## 成绩

阈值都在开发数据上定，测试集只用来报成绩；测试集看过不止一次的地方都标了出来。括号里是 95% Wilson 区间。完整记录在[设计文档](docs/superpowers/specs/2026-10-02-jianjin-design.md)第 6 节。

### 在公开的「成功示范」里找坏示范

五个公开数据集，来自 LeRobot Hub，机型是 SO-100、SO-101 单臂和双臂，共 308 条，发布者都当成功示范发布。拣金标出 32 条：存疑 26 条（8%），作废 6 条。

- **确有问题，16 条**：
  - 3 条不到 1 秒；
  - 3 条手臂几乎没动。其中 1 条看过视频，14 秒里手臂没动，最后一帧伸进来一只人手；另外 2 条只看了关节数据；
  - 1 条录的是人在复位方块，不是示范；
  - 9 条视频比关节数据长，看过的两条，多出来的都是复位画面。
- **看视频确认是误报，7 条**：方块叠得太正，下面那块被挡住，模型认不出叠好了；放方块时手臂长时间挡在上面，或者拿着方块绕了一圈；毛巾叠好了，模型给的最高进度却偏低。
- **还没核，9 条**：本机没有这几条的视频。

### 考卷 A：在真机成功示范上人工注入缺陷

这些失败是人为造出来的，不是真实失败。测试集换了任务，也换了机型（SO-101、双臂）。

| 缺陷 | 测试集检出（时间点也对） | 原样示范被报出 |
|---|---|---|
| 截掉结尾 → 没做完 | 197/201 = 98%（95% 到 99%） | 0/202 |
| 插入静止帧 → 停顿过长 | 199/201 = 99%（96% 到 100%） | 0/202 |
| 换掉任务描述 → 指令不符（视频） | 184/201 = 92%（87% 到 95%） | 10/201 = 5%（3% 到 9%） |

「没做完」改过一次换算方法，以适应双臂数据，所以这一行是测试集第二次看的结果；阈值仍然只在开发集上选。

### 考卷 B：RoboVAD 的真实异常

[RoboVAD](https://arxiv.org/abs/2609.17843) 是机械臂操作视频的帧级异常检测基准。拣金零样本，没有在 RoboVAD 上训练。

| 设置 | 帧级 micro/macro AUC | 和论文的 9 个方法放在一起排第几 | 论文里唯一用关节数据的方法（FIDeL） |
|---|---|---|---|
| in_domain | 66.9/65.6 | 4 | 56.3/54.0 |
| cross_anomaly | 68.4/67.0 | 3 | 52.1/53.4 |
| cross_task | 60.2/60.2 | 5 | 58.1/53.7 |
| cross_task+anomaly | 56.4/53.9 | 7 | 63.2/51.2 |

- 论文的方法都在 RoboVAD 上训练过，其中最好的比拣金高 11 到 28 个点（micro AUC）。
- 按整条示范计（test 629 条）：有异常的示范 158/387 = 41%（36% 到 46%）被标存疑，正常的 24/242 = 10%（7% 到 14%）。
- 「进度回落」这条规则单独看：检出 121/387 = 31%，正常示范被报出 21/242 = 9%。这是 test 第二次看的结果。

### 能说的和不能说的

- 能说：在真机录的真数据上，拣金能挑出坏示范、说清原因，每个数字都带分母。
- 不能说：用拣金筛过的数据训出的策略更好。这一条只引用已发表的结果（CUPID，CoRL 2025；DemInf，RSS 2025），等有机器人或数采场试点再测。
- 误报还在：方块叠得太正、手臂长时间遮挡，都会骗过视频模型；按整条示范计，视频规则在 RoboVAD 上只抓到三成异常。

## 怎么跑

需要 Python 3.12 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
uv run jianjin check <数据集目录> --out report.html --json findings.json
```

能读 LeRobot v3、RoboMIND HDF5 和 RoboVAD 目录。不加 `--judges` 时只跑关节体检，只用 CPU。

视频评判要 GPU：先在 Colab 上用 `notebooks/` 里的笔记本跑，得到一批缓存文件，放进 `cache/` 以后：

```bash
uv run jianjin check <数据集目录> --judges robometer --camera observation.images.top --out report.html
```

本机有视频时，报告会给存疑、作废的示范配关键帧；`--no-frames` 关掉。

考卷和测试：

```bash
uv run --extra hub jianjin fetch exam_a   # 下载考卷 A 的公开数据，默认只下关节数据
uv run jianjin eval a --split dev          # 考卷 A 开发集；测试集用 --split test
uv run jianjin eval b-episode --split train
uv run pytest
```

## 目录

```
src/jianjin/
  ingest/       读 LeRobot v3、RoboMIND、RoboVAD
  checks/       关节和元数据规则；video.py 是视频规则
  judges/       视频评判适配器（Robometer、TOPReward）和缓存
  diagnose.py   合并成判定
  report.py     离线网页报告；keyframes.py 配关键帧
  eval/         三张考卷
notebooks/      在 Colab 上跑视频评判的笔记本
configs/        考卷用的数据集、切分和授权
results/        考卷成绩（JSON，只有汇总数）
docs/           设计文档、实现计划、背景资料
```
