# 拣金 jianjin

[English](README.md)

数采场示范数据的自动质检。录完的每条遥操作示范，拣金自动判成「合格」「存疑」「作废」，写清原因和出问题的时间点：质检员只看存疑的，作废的每条都有依据。全部在本地跑，报告是一个断网也能打开的网页文件，数据不出场。

参赛：首届「海创π」未来产业创新创业大赛·具身智能专项赛；Nebius × NVIDIA Global AI Hackathon 的 Physical AI 赛道。

## 为什么做

具身智能的训练数据过去几年主要靠遥操作采集：采集员操纵主臂，机器人跟着做，录下视频和关节数据。国内为此建了一批数采场，据《中国经营报》统计，规模较大的至少 15 座。据报道，数采场的质检和标注大量靠人工；一位大型数采场负责人估计，采 100 小时可能只有 50 小时有效。作废的原因有没有告诉采集员，报道里没写；我们的判断是很少回流，同样的错下一班还会再犯。出处和逐条核对见[背景资料](docs/research/2026-10-02-background.md)。

拣金做两件事：

1. 机器先筛一遍，人只看机器拿不准的。
2. 说清原因：哪一秒、哪一类问题，可以按采集员汇总，每班反馈。

## 怎么判

| 看什么 | 查什么 | 报出的原因 | 要什么 |
|---|---|---|---|
| 元数据和关节读数 | 读数缺失；时间戳丢帧或倒退；示范过短；视频比关节数据短 | 数据异常（客观硬规则，一条就作废） | CPU |
| 元数据 | 视频比关节数据长，两路没对齐 | 数据异常（存疑） | CPU |
| 关节 | 中途停住太久 | 停顿过长 | CPU |
| 关节，和同任务那批示范比 | 路程远超常态；收尾姿态不像做完了；整条几乎没动；夹爪开合次数比常见的多；用时比常见的长很多 | 多余动作、没做完、空录、二次抓取、动作不流畅 | CPU |
| 视频评判（Robometer-4B，零样本） | 全程进度比同任务那批低得多；进度突然往回掉 | 指令不符、物体掉落 | GPU，结果缓存 |
| 视频评判（TOPReward，包 Qwen3-VL-4B，零样本） | 问模型「视频里的机器人完成了这个任务吗」，结尾答「是」的概率比同任务那批低得多 | 指令不符 | GPU，结果缓存 |

判定偏保守，错杀一条好数据比漏掉一条坏数据贵：

- **作废**：客观硬规则触发；或者两个独立来源（关节规则算一个，每个视频模型各算一个）指向同一处问题，比如两个视频模型都报同一条「指令不符」。
- **存疑**：有发现，但够不上作废，要人看。
- **合格**：什么都没报。没查的项目（比如没有视频、同任务示范太少、这批示范收尾姿态本来就不固定）单独列出，不当成通过。

报告里有整批的判定漏斗、问题分布、按采集员的统计（数据里有采集员编号时），以及每条示范一张体检单：判定理由、进度曲线、出问题的时间段、关键帧缩略图。

## 成绩

阈值都在开发数据上定，测试集只用来报成绩；测试集看过不止一次的地方都标了出来。括号里是 95% Wilson 区间。完整记录在[设计文档](docs/superpowers/specs/2026-10-02-jianjin-design.md)第 6 节。

### 在公开的「成功示范」里找坏示范

五个公开数据集，来自 LeRobot Hub，机型是 SO-100、SO-101 单臂和双臂，共 308 条，发布者都当成功示范发布。拣金标出 39 条：存疑 33 条（11%），作废 6 条。

- **确有问题，18 条**：
  - 3 条不到 1 秒；
  - 3 条手臂几乎没动。其中 1 条看过视频，14 秒里手臂没动，最后一帧伸进来一只人手；另外 2 条只看了关节数据；
  - 1 条录的是人在复位方块，不是示范；
  - 1 条方块放进了盒子，但手臂还在往回收，录制就结束了；
  - 1 条叠毛巾时右手没抓牢毛巾角，松开以后重抓（RoboMIND 把这种判为二次抓取）；
  - 9 条视频比关节数据长，看过的两条，多出来的都是复位画面。
- **看视频确认是误报，12 条**：方块叠得太正，下面那块被挡住，模型认不出叠好了；叠方块时手臂长时间挡在上面，或者拿着方块绕了一圈；毛巾叠好了，模型给的最高进度却偏低；放方块 5 条都放进盒子了，只是模型给的分比同批略低（4 条只有 TOPReward 报，1 条只有 Robometer 报）。
- **还没核，9 条**：8 条本机没有视频（分拣 3 条、乐高块 4 条、叠毛巾 1 条），其中乐高块 1 条是新加的「二次抓取」，读数看是放手时张得比平时大，多半是误报；放方块 1 条有视频但看不清：TOPReward 的「指令不符」是误报，新加的「二次抓取」读数像是第一下没抓住、张开重抓，顶上的相机被夹爪挡住了。

### 考卷 A：在真机成功示范上人工注入缺陷

这些失败是人为造出来的，不是真实失败。测试集换了任务，也换了机型（SO-101、双臂）。

| 缺陷 | 测试集检出（时间点也对） | 原样示范被报出 |
|---|---|---|
| 截掉结尾 → 没做完 | 197/201 = 98%（95% 到 99%） | 0/202 |
| 插入静止帧 → 停顿过长 | 199/201 = 99%（96% 到 100%） | 0/202 |
| 换掉任务描述 → 指令不符（Robometer） | 184/201 = 92%（87% 到 95%） | 10/201 = 5%（3% 到 9%） |
| 换掉任务描述 → 指令不符（TOPReward） | 128/201 = 64%（57% 到 70%） | 0/201 = 0%（0% 到 2%） |
| 换掉任务描述，两个视频模型都报 → 作废 | 115/201 = 57%（50% 到 64%） | 0/201 = 0%（0% 到 2%） |

「没做完」改过一次换算方法，以适应双臂数据，所以这一行是测试集第二次看的结果；阈值仍然只在开发集上选。TOPReward 试了两种提示格式，格式、分数和阈值都在开发集上选，测试集只看了一次。

### 考卷 B：RoboVAD 的真实异常

[RoboVAD](https://arxiv.org/abs/2609.17843) 是机械臂操作视频的帧级异常检测基准。拣金零样本，没有在 RoboVAD 上训练。

| 设置 | 帧级 micro/macro AUC | 和论文的 9 个方法放在一起排第几 | 论文里唯一用关节数据的方法（FIDeL） |
|---|---|---|---|
| in_domain | 66.9/65.6 | 4 | 56.3/54.0 |
| cross_anomaly | 68.4/67.0 | 3 | 52.1/53.4 |
| cross_task | 60.2/60.2 | 5 | 58.1/53.7 |
| cross_task+anomaly | 56.4/53.9 | 7 | 63.2/51.2 |

- 论文的方法都在 RoboVAD 上训练过，其中最好的比拣金高 11 到 28 个点（micro AUC）。
- 按整条示范计（test 629 条，关节规则加两个视频模型）：有异常的示范 247/387 = 64%（59% 到 68%）被标出，其中 7 条作废；正常的 33/242 = 14%（10% 到 19%）被标出，没有作废。加「动作不流畅」以前是 238/387，加「二次抓取」以前是 171/387，正常的都是 33/242；只用 Robometer 时是 158/387 和 24/242。
- 「二次抓取」这条规则单独看（只用关节数据，参照是 train 的正常示范）：抓空或掉落的示范检出 243/325 = 75%（70% 到 79%），有任何异常的 258/387 = 67%（62% 到 71%），正常示范被报出 0/242（0% 到 2%）。train 里见过的三个任务抓空或掉落 187/193 = 97%，没见过的倒米、套环 56/132 = 42%。这是 test 第二次看的结果：第一次以后，为了乐高块上放手时一闪的误报，加了「在一档里待不够 0.2 秒又回去的不算」。
- 「进度回落」这条规则单独看：检出 121/387 = 31%，正常示范被报出 21/242 = 9%。这是 test 第二次看的结果。
- TOPReward 的「进度回落」在 test 上检出 71/387 = 18%，正常示范被报出 12/242 = 5%（只跑一次）。但它在开发数据集的成功示范上误报太多（放方块 50 条报了 40 条，都是开头几帧打分不稳），没启用。

### 考卷 C：北京人形质检判不合格的真示范（RoboMIND）

RoboMIND 公开了 1,678 条质检判不合格的遥操作示范，原因分 11 类，但没有同一批采集的成功示范。拣金只读其中的关节数据，参照用同任务里别的原因的示范，所以「其他原因被报出」不是误报率：那些示范也是失败的。任务按开发、测试分开，在看任何指标之前定死。

| 原因 | 拣金的规则 | 检出 | 同任务其他原因被报出 |
|---|---|---|---|
| 二次抓取（284 条） | 夹爪开合次数比常见的多；参数在 RoboVAD 上定，没在 RoboMIND 上调 | 99/162 = 61%（53% 到 68%） | 72/1,085 = 7%（5% 到 8%） |
| 动作不流畅（557 条） | 用时比同任务中位数长 1.7 倍以上（测试集，只跑一次） | 26/187 = 14%（10% 到 20%） | 18/458 = 4%（3% 到 6%） |
| 速度过快（36 条） | 没加：和同任务比最快速度、平均速度，开发集 17 条一条没检出 | | |

- 数停顿次数、动作分段、jerk 这类平顺度指标，在 RoboMIND 上都反着报（开发集 AUC 0.31 到 0.45）：被标「动作不流畅」的示范，停顿和分段反而比别的原因少。同类开源工具也提过这一点（hflow 不拿平顺度判作废；一份对 SAL、TED 的审计发现它们量的多半是示范时长），这次是在真人质检的标签上量出来的。所以「动作不流畅」这条规则只看用时；它在成功示范测试集（444 条）上一条没报。
- 能比的不是全部：二次抓取 284 条里能比 162 条（天工仿真是灵巧手，认不出夹爪；小任务凑不够 5 条参照）；动作不流畅测试集 237 条里能比 187 条。

### 能说的和不能说的

- 能说：在真机录的真数据上，拣金能挑出坏示范、说清原因，每个数字都带分母。
- 不能说：用拣金筛过的数据训出的策略更好。这一条只引用已发表的结果（CUPID，CoRL 2025；DemInf，RSS 2025），等有机器人或数采场试点再测。
- 误报还在：方块叠得太正、手臂长时间遮挡，都会骗过视频模型；按整条示范计，视频规则在 RoboVAD 上只抓到三成异常。RoboVAD 上两个视频模型都报、判作废的 18 条里，8 条没有异常标注，没看视频，不知道是模型错还是标注漏。
- 动作质量只查了一部分：RoboMIND 的 11 类原因里，大头是动作不流畅、二次抓取、多余触碰和夹取前碰撞，任务本身多半做完了。按类别名对，拣金有规则冲着它去的是「失败放置」「二次抓取」「动作不流畅」，954 条（57%）；但量过的两类检出差得远，二次抓取 61%，动作不流畅只有 14%。656 条（39%）查不了，多是要看画面的碰撞、多余触碰。对照表在设计文档第 5 节。

## 怎么跑

需要 Python 3.12 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
uv run jianjin check <数据集目录> --out report.html --json findings.json
```

能读 LeRobot v3、RoboMIND HDF5 和 RoboVAD 目录。不加 `--judges` 时只跑关节体检，只用 CPU。

视频评判要 GPU：先在 Colab 上用 `notebooks/` 里的笔记本跑，得到一批缓存文件，放进 `cache/` 以后：

```bash
uv run jianjin check <数据集目录> --judges robometer,topreward --camera observation.images.top --out report.html
```

本机有视频时，报告会给存疑、作废的示范配关键帧；`--no-frames` 关掉。

加 `--summary`，报告顶部多一节「本批小结」：NVIDIA 的 Nemotron（在 Nebius Token Factory 上，`nvidia/Nemotron-3_5-Lightning`）写一段给质检组长和采集员看的话，中文、英文各一份。模型只看拣金算出的统计，不看原始数据；它写的文字里所有数字、示范编号、原因名都是占位符，由拣金按统计填，模型自己写的数字一律不收，不合格就退回模板。密钥读环境变量 `NEBIUS_API_KEY`，没设就用模板；回答按统计缓存在 `cache/summary/`，重出报告不再调用。2026-10-05 在叠方块那批上实测，中英两段都是模型写的，第一次就过了数字核对。

考卷和测试：

```bash
uv run --extra hub jianjin fetch exam_a   # 下载考卷 A 的公开数据，默认只下关节数据
uv run jianjin eval a --split dev          # 考卷 A 开发集；测试集用 --split test
uv run jianjin eval b-episode --split train
uv run jianjin eval b-regrasp --split train  # 二次抓取；test 加 --dev-result results/exam_b_regrasp_train.json
uv run --extra hub jianjin fetch robomind  # RoboMIND 失败示范只读关节：拉 1.75 GB、存 253 MB；先在 Hugging Face 同意条款并登录
uv run jianjin eval c --split dev          # 考卷 C；测试集加 --split test --dev-result results/exam_c_dev.json
uv run jianjin eval c-regrasp              # 二次抓取在 RoboMIND 上量一次
uv run pytest
```

## 还在做的

- TOPReward 的「进度回落」：模型看最开头几帧时打分不稳，要去掉开头那段在 train 上重定。
- 要看画面的动作质量问题（触碰多余、夹取前碰撞、目标移位等，RoboMIND 里 620 条）：留给能回答具体问题的视频模型，比如 Cosmos 3。
- 动作不流畅只抓到 14%，速度过快和同任务比关节速度没有信号：这两类要先弄清质检员看的是什么。

## 目录

```
src/jianjin/
  ingest/       读 LeRobot v3、RoboMIND、RoboVAD
  checks/       关节和元数据规则；video.py 是视频规则
  judges/       视频评判适配器（Robometer、TOPReward）和缓存
  diagnose.py   合并成判定
  report.py     离线网页报告；keyframes.py 配关键帧
  eval/         三张考卷
notebooks/      在 Colab 上跑视频评判的笔记本
configs/        考卷用的数据集、切分和授权
results/        考卷成绩（JSON，只有汇总数）
docs/           设计文档、实现计划、背景资料
```
